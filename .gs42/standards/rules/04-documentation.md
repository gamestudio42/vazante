# Documentation

- Update the design note when player-facing behavior changes: what the
  player can do now, what they cannot, and which pillar it serves.
- Follow the generators used by the current repository. Do not hand-edit
  generated files; edit the source they are built from.
- Keep public docs generic. Do not put internal backlog items, private
  URLs, or unreleased schedule dates in a public README.
- Write generic product documentation in English unless the repository
  states a documented exception.
- Art direction, species lists, palette, and fantasy live in the
  project. Link to them. Do not paste a one-off visual rule into a
  global comment that the next game would inherit by accident.
- When a feature is cut, say so in the design note instead of leaving a
  dead system that looks intentional.
