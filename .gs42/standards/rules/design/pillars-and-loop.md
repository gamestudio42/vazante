# Pillars and core loop

A GameStudio42 game is judged by what the player does and feels, not by
the size of the feature list.

## Read first

In the live repository, read whatever states the fantasy and the loop:

- README and any design note, pillar list, or one-pager
- The opening scene, first level, or first minute of play
- Recent playtest notes that name a pillar

If the repository has no written pillars, infer them from the playable
slice and say that you inferred them. Do not invent a fantasy the build
does not already support.

## Rules

- Name the player fantasy in one sentence: who the player is and what
  they are trying to make happen.
- Keep three to five pillars. A pillar is a promise the game keeps in
  play, not a marketing line.
- The core loop is the cycle the player repeats. Write it as verbs:
  act, read the result, decide, act again.
- Every feature names the pillar it serves and the loop beat it
  changes. If it serves none, cut it or recast it.
- Prefer one strong verb over several weak ones. A new verb needs a
  reason the existing verb cannot carry the fantasy.
- Do not add a system to "make it a real game" (skill tree, second
  currency, daily quests) unless a pillar needs it.
- When two features compete for the same minute of play, keep the one
  that makes the fantasy clearer.

## Conflicts

Repository design docs win over this file when they name different
pillars. Report the conflict. Do not silently retcon the game.
